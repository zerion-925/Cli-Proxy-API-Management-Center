# Isolated browser demo

These files are **synthetic test fixtures**, not production usage or a live-proxy integration. The demo imports the real dashboard meter, theme, translations, session store and central authenticated API client. No fixture is imported from `src/` or production build entrypoints. The UI is also mounted in the normal hash-routed dashboard.

Use repository-pinned Bun 1.4.3. In two local terminals from the frontend repository:

```bash
bun tests/browser/usageMeterFixtureServer.ts
bun run dev --host 127.0.0.1 --port 18418 --strictPort
```

Open `http://127.0.0.1:18418/tests/browser/usage-meter.html`. The server binds only loopback on18419, requires the explicitly synthetic management bearer in the harness, and permits CORS only from the exact local Vite origin. Do not expose either server remotely. There are no production keys, inference calls, or paid APIs.

Controls above the meter exercise ready, empty, unsupported404 and storage-error503 states. Meter controls exercise aggregate/per-client query filters,24h/7d/30d/90d, UTC model/time tables and refresh. The isolated logout control exercises immediate data clearing. Toggle theme demonstrates existing theme tokens. The fixture does not model real delivery or historical availability; backend verification is in the sibling plugin runtime integration tests.

Browser checks performed with Chromium: summary/timeline/totals/table; aggregate501 attempts versus native167 and plugin334; selected opaque IDs transmitted on exact plugin path;7d day breakdown; error/unsupported/empty states; logout data clearing; no page-level overflow at390px. Desktop and mobile screenshots in `screenshots/` are explicitly synthetic. Table region is keyboard-focusable and horizontally scrollable, not compressed into unreadable cells. Zero token counters during active collection are displayed unavailable because the ABI cannot distinguish missing measurements from true zero; uncached input is not inferred by subtraction.

The `official-runtime` control serves the checked-in wire snapshot generated by the actual compiled plugin loaded in the official proxy, with a loopback upstream stub:3 attempts,2 succeeded,1 failed,240 tokens,2 clients,1 duplicate. This is a recorded response from synthetic traffic, not an active proxy connection or fabricated JSON. That mode intentionally supports aggregate24h only; unsupported filters return400 rather than presenting unfiltered data as per-client usage. `tests/clientUsageMeter.test.ts` validates this captured response through the production normalizer. Regenerate it from the plugin repository using `METER_RUNTIME_SNAPSHOT=/absolute/frontend/tests/fixtures/usage-meter-official-runtime.json make runtime`.

The app uses no browser history collector and persists no client selectors, IDs, usage snapshots or client keys. Only the app's existing auth store is used; the test management value is synthetic. Run this demo in an isolated browser profile, not one containing production remembered sessions.
